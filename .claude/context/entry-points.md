# Entry points

MV3 extension with four entry points. All share React components from `src/shared/`. Manifest is generated by `manifest.config.ts`.

## Background service worker

`src/background/index.ts` is a minimal worker. It routes `chrome.action.onClicked` to `chrome.sidePanel.open()` and runs the `onInstalled` hook that triggers dev seeding when `NODE_ENV === development` and injects GitHub credentials from dev env vars.

## Content script

`src/content/main.tsx` mounts a React root in a shadow DOM adjacent to the detected chat input. Shadow DOM isolates extension styles from the host page's CSS. The script also syncs dark mode by observing `documentElement` class / `data-theme` / `data-color-scheme` attributes on the host page and mirroring them into the shadow root, so the dropdown matches the host's theme without relying on `prefers-color-scheme` alone.

## Sidepanel primary, popup dormant

The extension icon opens the sidepanel via `chrome.action.onClicked` → `chrome.sidePanel.open()`. The popup entry point (`src/popup/`) is kept dormant for rollback but is not wired into the manifest's `action.default_popup`. Removing it is a follow-up cleanup, not blocking.

## Shared UI between popup and sidepanel

Popup and sidepanel import the same React components from `src/shared/`. Only layout/width differs. This keeps prompt management logic in one place regardless of which surface is active.

## Options page composition

`src/options/app.tsx` is a layout coordinator. It owns the single `useSettings` instance (see [forms](forms.md)) and composes three sections: `data-section.tsx`, `site-config-section.tsx`, and `github-section.tsx`. Each section receives `settings`, `updateSettings`, and `updateSiteSettings` as props.

## shadcn/ui constraints

Components in `src/shared/components/ui/` are source of truth. Project-wide baseline defaults (such as focus ring width) may be modified directly in the primitive. Override per-component appearance via `className` props at the usage site.

## Risks

- MV3 service worker lifecycle: the background script can be killed at any time. No persistent state lives there.
- The content script's site-observer selectors are the fragile boundary, since ChatGPT and Claude.ai DOM evolves frequently.
